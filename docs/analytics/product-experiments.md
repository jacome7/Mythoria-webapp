# Product experiment release and readout

All three windows ship empty in `src/lib/product-experiments/release.ts`. Before scheduling the mobile idea entry, record the date when the seven-day v2 reconciliation passed. Add a reviewed UTC start and exclusive end for each experiment, in order. Windows may have gaps. An overlap, a skipped predecessor or a missing baseline prevents enrollment. Emptying the windows immediately stops new assignments and reader diagnostics on that revision. Keep previous windows in the configuration during follow-up.

The assignment unit is one consenting first-party browser receipt, allocated 50/50 on its first eligible visit. A unique database key keeps retries and simultaneous tabs in one arm. No new browser identifier is issued by the experiments. Withdrawal stops collection and invalidates the receipt. A new receipt or another device is a new browser participant. Link outcomes only through the existing restricted receipt-to-author binding.

| Experiment        | Common eligibility for both arms                                                                                           | Treatment                                                                                                                      |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Mobile idea entry | Visible mobile homepage below 768 CSS pixels, fresh browser draft and readable storage                                     | Optional short text entry at the main CTA. The idea follows the usual campaign and sign-up return in the current tab.          |
| Reader CTA        | Successfully loaded public chapter                                                                                         | Offer a link to the wizard after the chapter and send the last chapter’s existing creation link directly to the wizard.        |
| Offer clarity     | Pricing page with a known account state, standard eBook price and an effective starting grant or current signed-in balance | Explain cost, funds available and, when necessary and available, an active credit package sufficient to cover the balance gap. |

Both arms require Analytics consent and an active receipt on the canonical site. Tag previews and automated browsers are excluded. Keep access to the original experience for other visitors. The assignment request accepts only bounded actions and the experiment name. Reader completion means the end of a public book’s final chapter entered the visible viewport. Reading observations apply for seven days following assignment in all three experiments.

## Reproducing the readout

Execute `product-experiment-readout.sql` with psql on the restricted analytical replica at an explicit UTC cutoff. Provide the WebApp tables in the search path and a relation `workflow_usage` containing only `story_id, created_at, estimated_cost_in_euros` from SGW’s `workflows_db.token_usage_tracking`. Keep both snapshots consistent through the cutoff. Exclude known test orders and fixture accounts from the reporting replica; explicit Stripe test payments are excluded by the query as well. Never copy input prompts, customer text or the remaining workflow columns into the report.

The D7 and D30 denominators are all assigned browsers whose entire window elapsed, including unlinked or withdrawn receipts. Numerators use the first completed generated story owned by the linked author and first positive completed payment in their full transactional history. Pre-assignment completions do not qualify. A second device linked to the same author cannot double-credit either outcome inside an experiment. The earliest assigned device owns that author’s outcomes. Unlinked, withdrawn and ambiguous historical records are reported to show ascertainment limits. A later refund affects revenue reconciliation separately. Use percentage-point differences, absolute counts, missing timestamps, reader completion and its denominator, p95 terminal generation time, timed/started run counts, and estimated SGW spend with cost coverage. Missing cost is unknown. Compare spend per assigned mature participant, then reconcile it to provider billing before increasing exposure.

Record privacy sentinel counts and consent withdrawal checks from the approved release audit beside this readout. Stop exposure for a leak or a material guardrail regression. Record the agreed minimum counts or precision before enrollment and extend observation when they are unmet. Review GA4 key events and Google Ads campaign-level overrides independently. Purchase stays the primary Ads purchase goal. Diagnostic clicks remain ordinary events. Preserve the cutoff, deployment revision, configurations, count differences and decisions with the release evidence.
