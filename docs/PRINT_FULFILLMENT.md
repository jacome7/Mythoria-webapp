The active rates are 22 credits for the first copy, 18 for each additional copy, and 5 per order for shipping. One copy costs 27 credits and two cost 45, with no chapter surcharge. ## Staff workflow

Open **Tickets → Print fulfillment settings** in Admin to set the default provider, maximum landed EUR per copy, and hardcover credit price. The initial provider is **None (manual fulfillment)**. The default selects the production profile for new orders. A physical print purchase pays Mythoria with credits. A Lulu job can incur a separate supplier charge, depending on the payment settings in Mythoria’s Lulu account.

1. The paid order appears on a print-request ticket. Wait for the current proof version to show successful email delivery. The purchaser receives the existing print-order confirmation with the interior PDF and wraparound cover. For oversized pairs the email includes private download links. The configured Reply-To mailbox receives customer replies.
2. Check that mailbox using the order reference before dispatch. Staff choose the review period. Place the ticket on hold if there is a concern. Record the correction, prepare a revised proof, and check that the new version has been sent. For a proposed shipping-address correction, obtain customer confirmation and record the corrected details on the held ticket.
3. For a manual order, dispatch the reviewed pair to the printer from the linked ticket. In an approved Lulu environment, choose **Prepare for Lulu** on an individual ticket to prepare its supplier-specific cover and interior. Review the replacement proof, binding, copy count, shipping service, and total supplier quote.
4. **Submit to Lulu** releases the current version. Check the inbox and confirm the displayed amount. A hold, changed quote, excessive cost per copy, failed QA, or missing proof delivery prevents release. Ticket resolution is a separate staff action.
5. If a supplier call times out, reconcile the existing job and line references. Check the Developer Portal before considering any replacement. An unpaid supplier order can still exist. A manufacturing error or carrier delay needs investigation. Retain identifiers, actual costs, dates, tracking details and photos for supplier claims. Confirm cancellation and refund status separately with Lulu. Track the claims deadline from the shipment date.

## Configuration and deployment order

- Provision a dedicated private Cloud Storage bucket, separate from public story assets. Configure the same `PRINT_PROOF_BUCKET` on SGW and WebApp. Give SGW object creation and read access, and WebApp and Notification Engine read access. Configure WebApp’s signing identity with the ability to sign GCS download URLs. Restrict support access and apply the organization’s retention policy to both proof files and attachment snapshots in the email delivery ledger.
- Deploy Notification Engine’s proof endpoint, SGW’s authenticated order-proof renderer and its native print dependencies, and the ticket-aware Admin service before switching paid checkout to the new code. Apply the WebApp-owned additive Drizzle migration using its normal reviewed migration procedure. Keep unrelated working-tree changes out of release artifacts.
- For square Lulu proofs, deploy the SGW renderer that accepts and echoes `coverPageCount` before the Web App. Use **Prepare proof and quote** to refresh a legacy proof on a ticket that is still awaiting release. The worker gives the replacement a new proof version and private file pair. Orders already submitted or awaiting reconciliation keep their existing supplier references.
- Stage the Admin revision first. Existing WebApp traffic continues using the legacy ticket endpoint. The new WebApp posts to `/api/tickets/paid-print` with `fulfillmentVersion: 1` and verifies the returned print request reference before charging credits. Set Admin’s `PRINT_INTERNAL_AUDIENCE` at the WebApp cutover when the command API is available.
- Configure `PRINT_INTERNAL_AUDIENCE` identically on Admin and WebApp. Set WebApp’s `PRINT_ADMIN_SERVICE_ACCOUNT` and `PRINT_SCHEDULER_SERVICE_ACCOUNT` to the respective caller identities. The WebApp, SGW, Admin and Notification Engine service URLs and service API keys must match the target environment. Configure the print variables on the target Cloud Run services. WebApp Cloud Build preserves those runtime values.
- Checkout requires the private proof bucket, both service accounts, the internal audience and service API keys before it can accept payment. Configure the services, apply migration `0052_print_fulfillment` and enable the proof worker before directing purchases to the new revision.
- Create the proof worker schedule using WebApp’s `scripts/setup-print-scheduler.ps1` with project, region, WebApp URL, audience, and scheduler identity. Use `-WhatIf` to preview. It posts to `/api/internal/print/jobs/reconcile` every five minutes. Allow the scheduler identity to invoke the endpoint. Verify one synthetic manual checkout produces one ticket, one debit and one confirmation. The worker never authorizes supplier purchases.
- For Lulu, set `LULU_PRINT_ENVIRONMENT` to `sandbox` or `production`, the matching `LULU_PRINT_CLIENT_KEY`, `LULU_PRINT_CONTACT_EMAIL`, and bind `LULU_PRINT_CLIENT_SECRET` via Cloud Run Secret Manager (`LULU_PRINT_CLIENT_SECRET:latest`) or `.env.local` for local sandbox testing. Sandbox requires its own key and separate secret. Configure one environment per deployment/database to keep jobs, proof URLs and webhook signatures isolated.
- Set `LULU_PAPERBACK_POD_PACKAGE_ID` to `0583X0827.FC.PRE.PB.080CW444.MXX` (32–800 interior pages) and `LULU_HARDCOVER_POD_PACKAGE_ID` to `0583X0827.FC.PRE.CW.080CW444.MXX` (24–800). Both are A5, Premium Color, matte, coated white stock. Set a positive inclusive EUR-per-copy ceiling. Activate `printedHardCover` in credit pricing only after setting the customer price. Keep the default **None** until operations chooses Lulu.
- Register the environment’s HTTPS WebApp callback at `/api/print/lulu/webhook` for `PRINT_JOB_STATUS_CHANGED` via the Lulu Webhooks API (`POST /webhooks/`, `GET /webhooks/`, `PATCH /webhooks/{id}/`). `ensureConfiguredLuluWebhook()` automatically registers and re-activates the subscription from `POST /api/internal/print/jobs/reconcile` and `submitPrintOrder`, or run `npx tsx scripts/register-lulu-webhook.ts` to trigger it manually. Verify webhook activity, failed submissions, overdue proofs, email delivery outcomes, rejected files, pending supplier payments and uncertain orders. Reconcile missed updates against the supplier job details.
- Before enabling production release, exercise the synthetic sandbox lifecycle. Obtain approval to order a physical paperback and casewrap proof. Check pagination, gutters, bleed, color, spine and hinges, packing slip, return address, tracked shipping, landed cost and delivery time. Confirm supplier payment mode, billing, privacy terms and retention with operations.

## Premium square hardcover

The premium edition uses the existing hardcover credit rate, extra-copy rate and shipping rate without a chapter surcharge. New editions have 33 interior pages, including the localized Mythoria invitation on page 33. Published 32-page editions and already paid orders keep their original pagination. **None** selects manual production for new square orders, and **Lulu** selects automated supplier preparation. A5 hardcover still requires the Lulu default.

Keep `PREMIUM_SQUARE_PRINT_APPROVAL` unset until the owner approves the delivered physical proof for the 33-page format. Retain the edition revision, interior and cover digests, physical copy reference, decision and date. For a Lulu approval, also record the target environment, package, normalized page count and cover dimensions. Check that page 33 prints on the right, record any added blank leaves and confirm the exact count reported by the normalization API for the square package. [Lulu interior formatting guide](https://help.lulu.com/en/support/solutions/articles/64000255590-interior-formatting-the-basics)

Open a staff proof from the published premium edition in Admin. Enter the staff shipping address and create the ticket. The WebApp reserves one copy per story and revision, without debiting credits or emailing the customer. Open the ticket to review and release the prepared manual proof or choose **Prepare for Lulu** to obtain the validated supplier files and quote. This flow works while public checkout is closed. The WebApp link uses `/api/tickets/staff-print` and persists the acknowledged ticket ID before preparation.

On 2026-11-25, the owner approved the physical square hardcover proof of _Bea e o Macaco no Nariz_ and approved accepting customer orders with manual fulfillment. The story reference is `e73bf537-a17a-4721-9c72-048fbd385c97`. The physical copy reference, edition revision and PDF digests were unconfirmed at sign-off. Lulu validation remains a separate approval.

To activate that approval, set the WebApp runtime variable `PREMIUM_SQUARE_PRINT_APPROVAL=manual:premium-square-hardcover-2026-11-25` with **None** selected in **Tickets → Print fulfillment settings**. Before opening checkout, deploy the compatible services, verify the paid-print worker, and confirm active `printedHardCover`, `extraBookCopy` and `shippingCost` rates. Set the hardcover rate to the approved customer price in Admin. Manual orders use the linked ticket for staff dispatch.

Keep **None** as the provider during the Lulu pilot. Qualify the 8.5 × 8.5 in casewrap package `0850X0850.FC.PRE.CW.080CW444.MXX` in `LULU_PREMIUM_SQUARE_POD_PACKAGE_ID`. Record authorization for one staff proof with `LULU_PREMIUM_SQUARE_STAFF_PROOF_APPROVAL=<environment>:<pilot-record>`. Use a synthetic edition and a staff delivery address. Release one copy explicitly on the ticket, pay per job in the Lulu portal and retain the physical proof evidence. Close the staff pilot by removing its approval when the proof is complete.

For customer release after the physical proof, set `PREMIUM_SQUARE_PRINT_APPROVAL` to `production:<approval-record>` or `sandbox:<approval-record>` for the matching environment. Set `LULU_PREMIUM_SQUARE_CUSTOMER_COUNTRIES` to comma-separated uppercase ISO country codes for active, qualified markets. An unset, blank or malformed list closes customer Lulu preparation and release. Validate tracked quotes, including tax and multiple copies, against the configured landed EUR ceiling in each current market (PT, ES, FR, DE, IE, IT, NL, BE, GB). The customer continues to pay with Mythoria credits. Staff prepare eligible tickets individually, then pay each released job in Lulu. The webhook URL defaults to `NEXT_PUBLIC_BASE_URL`; set `LULU_WEBHOOK_BASE_URL` only when the environment requires a different public HTTPS origin.

Checkout freezes the current published private manifest by key, generation, SHA-256 and interior page count. Lulu preparation validates the pinned interior before sizing the cover and quoting. It accepts an unchanged page count or one supplier-added blank page for a 33-page edition. The worker checks the final pair's geometry and hashes, validates the cover and emails that exact pair or private links. An unexpected page count, package, address or shipping service needs staff review. Staff check the inbox, review the current proof and confirm the landed quote before using **Release square order to Lulu**. The render, mail and status workers never submit a supplier job.

Place the ticket on hold before binding a correction. Publish the corrected immutable manifest as a direct successor of the ticket’s edition with the same page count. Enter the new revision ID and reason on the ticket. The order records its previous edition, proof, quote, actor and reason, and advances the proof version. Clearing the hold queues the replacement pair and email without charging again. A shipping-only correction keeps the frozen edition and also advances the proof version. Investigate an uncertain or submitted job through reconciliation before handling a cancellation or replacement.

## Order recovery and address preflight

The customer checkout saves an opaque attempt ID in the tab before submitting. The signed-in purchaser can recover the original order after reloading. WebApp links the ticket before the one-time debit. Admin creation uses a separate intent and preserves one proof per published square revision. An intentional additional shipment gets its own order and ticket.

Square Lulu preparation checks shipping against the frozen edition’s page count before rendering. A5 checks after initial pagination. When normalization changes the final count, preparation requotes for that count. Material address changes hold the order before proof email or supplier submission. Whitespace differences and changes of case in city, country or subdivision alone are accepted. A manager sees the proposed address fields on the held ticket. Saving a confirmed correction advances the proof version, invalidates the quote and preserves the purchaser’s address book. Clear the hold to prepare the replacement proof.

## Shipping address review

The paid checkout returns HTTP 400 with `shipping_address_review_required` before creating a new order if the street line matches the recipient or account name and the second address line is present. The checkout opens the saved address for correction. Editing that address updates the profile for future purchases. For an existing order, confirm the address with the customer and correct the order's shipping address separately in its Admin ticket.

## Rollback and existing orders

Clear `LULU_PREMIUM_SQUARE_CUSTOMER_COUNTRIES` to pause new customer Lulu releases while **None** keeps manual sales open. To close new square checkout as well, remove `PREMIUM_SQUARE_PRINT_APPROVAL`. Preserve the paid-print worker, private buckets and Lulu environment required by existing tickets. A material change to the stock, binding, template geometry or renderer requires a new physical sign-off before reopening sales.

Switch the default to None to prepare new orders for manual production. Continue processing paid proofs, monitoring the reply inbox and reconciling submitted or uncertain jobs. Keep the immutable file pair available while a supplier may still fetch it. Legacy tickets lacking a verified paid-order link require the original manual workflow. Never attach the latest story-level PDFs to a new-format paid order.

Keep the WebApp command API and proof worker available for paid tickets through rollback. An older checkout tab receives a reload prompt when its request format is retired. New checkout tabs submit and recover through `POST /api/print-requests/checkout`. New Admin forms use `createAdminOrderV2` with a required intent ID. Those entry points only exist on the compatible WebApp. When it is restored, already reserved intents can still recover.

## Printing costs

The reconciliation worker records Lulu's tax-exclusive job price and original currency for production orders. Use migration `0055_print_fulfillment_costs` before releasing the worker or the Admin Printing Costs dashboard. EUR jobs retain their native value. For other currencies the worker uses the ECB reference rate on or before the UTC Lulu job date. Missing prices and conversions are retried and shown separately in Admin. Manual and sandbox orders carry no recorded Lulu production cost. The worker can backfill older production jobs when their order identity and price are available.

## Lulu packing slip references

Apply migration `0056_lulu_packing_slip_order_ids` before deploying the WebApp change. New Lulu submissions use the same eight-character order number as the proof email, with `-1` appended for the line item. The WebApp stores that reference before submission so webhooks and polling can recover an uncertain create. Existing Lulu jobs continue to reconcile by full request UUID. If two older print requests share a prefix, release through manual fulfillment to avoid submitting an ambiguous Lulu reference.

The Lulu Developer Portal setting to use Mythoria order and line item IDs controls what appears on the packing slip. After verifying the new reference in Lulu, enable it in **User Account → Packing Slip Information**.
